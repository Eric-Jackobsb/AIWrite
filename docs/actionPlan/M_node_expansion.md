## §4 四层拆解：四种「扩展」的含义

> 同一句「要做 nodes 的扩展」，在下面四层里是四件**成本 / 合法性差一个数量级**的事。本节的目的是**摊开**，不是排序。

### 4.1 总览（判据全部来自 §2 取证与 §3 约束）

| 层 | 一句话 | 新增节点？ | 撞 §十 / §4.4 | 撞 §19.1 | 改动面（依据） | 用户可感知度 |
|---|---|---|---|---|---|---|
| **L1** | **不加节点，把现有 8 个做深**（参数 / 后端 / 行为） | ✗ | ✅ 零冲突 | ✅ **完全未被提及** | 注册表参数 + 执行器实现（`source/nodes/src/`）；`api_probe` 参数类断言同步；文档 4~6 处 | 中（「能调的更多了」） |
| **L2** | **新增节点类型**（文件读入 / 文本处理 / 数值控制…） | ✓ | ⛔ **正面冲突**（须推翻两处） | ⚠ 视频 / 音频输入已延后 | **2 处注册 + `api_probe.cpp:803/805` 硬断言 + 12~15 处文档** | 高（「多了一个积木」） |
| **L3** | **节点库 / 画布交互**（搜索 / 折叠 / 小地图 / 吸附 / 对齐线） | ✗ | ✅ 不撞 §十 | ⛔ **5 项全在延后清单** | UI 侧（`source/ui/src/`），不碰引擎契约；但需推翻 §19.1 对应行 | 高（「更好用」） |
| **L4** | **组合层**：示例工作流 / 模板 / 分享（**全用现有 8 节点**） | ✗ | ✅ 零冲突 | ✅ 未被提及（「工作流分享」在 §六「可选」栏） | `source/workflows/` + 示例载入入口 + `--exec-selftest` 断言；文档 3~5 处 | **最高**（「跑起来就看到效果」） |

### 4.2 L1：参数 / 后端扩展（「把现有节点做深」）

- **可选内容（举例，非清单）**：N-06 补 `top_k` / `stop` / 惩罚类 / JSON 输出；N-07 补 `seed`（与 N-06 对称）；N-04 补排序 / 前缀 / 带源标签；N-01 支持从文件导入；N-05 增加后端适配。
- **为什么便宜**：参数是 `Definition.params` 的**数据声明** + 执行器读取，且**已有条件可见机制**（§2.2）；不改节点数 ⇒ **不触碰 `api_probe.cpp` 第 803/805 行**。
- **撞约束吗**：§十 与 §4.4 **不涉及参数**；§19.1 的 14 项里**没有「参数级增强」这类条目** ⇒ **法律面上最干净的一层**。

### 4.3 L2：新增节点类型（「多一个积木」）

### 4.5 L4：组合层（「用现有 8 节点把能力兑现」）

## §5 代价边界：哪些想法**根本不属于「节点扩展」**

以下三项是「扩展 nodes」话题里出现频率最高、也最容易被误当成「再加一个节点」的：

| 想法 | 为什么不是「加节点」 | 需要的改动 | 已登记状态 |
|---|---|---|---|
| **条件分支** | 需要「**节点是否执行由上游值决定**」的**图级**语义 | 执行器调度（跳过 / 激活）+ 校验（悬空分支）+ UI（分支表示） | §19.1 延后 · 不排期 |
| **循环 / 批量** | 需要「**同一节点重复执行**」或「子图重复执行」 | 执行器支持**多轮遍历**与值覆盖 | §19.1 延后 · 不排期 |
| **子工作流** | 需要「**图套图**」：工作流成为可被调用的单元 | 契约新增「工作流实例」概念 + 参数映射 + 递归 / 深度限制 | §19.1 延后 · 不排期 |

**引擎侧现状（[../../source/engine/include/executor.h](../../source/engine/include/executor.h) 第 6–13 行 · 设计原文）**：

- 「单线程分帧：`tick()` 每帧推进**一个节点**（UI 调用）；无 UI 场景用 `runToCompletion()`」
- 「状态机：`Waiting → Running → Done / Error`；失败节点的下游标 `Skipped`，**无关分支继续**（§10.4）」
- 「运行态**值**只存在于 `Executor`（`NodeOutputs`），**不进入 Graph** —— Graph 是「文档」」

⇒ 三条合起来说明：**现有执行模型是「静态图 + 一次推进」**；上表三项都要求「**控制流**」能力，
属**执行引擎语义变更（v2 量级）** —— **不是**「2 处注册 + 文档同步」能承载的改动量（与 §2.5 的 L2 价格标签对照即知）。

> **口径建议（待拍板 · `NE-Q3`）**：把「条件分支 / 循环 / 子工作流」**从「节点扩展」议题中剔除**，
> 明确登记为「**引擎 v2 议题**」，避免它们在讨论中反复伪装成「再加一个节点」。

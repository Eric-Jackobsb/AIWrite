## §1 结论摘要（先读这一段）

**一句话**：网页版通道**没有「节点/运行 ↔ 窗口」的关系表** —— 全进程只有**一套**按**站点**键控的全局单例（窗口 / 脚本槽 / 上传槽 / 网络回执 / PoW / 会话等待），于是「**多个节点 + 多个 AI 运行**」时**无法精准定位 node 与 web 的对应关系**：同站点多节点互相认领同一页面、跨站点互相关窗、证据与上传槽互相覆盖；叠加「就绪 = 凭证级」的判据 ⇒ 真机表现为「**第一次假成功、第二次必失败**」（2026-10-06 三次运行实证）。

**四条修正主线**（详见 §4）：

1. **归属**（`W-D1` / `W-D2`）：引入 `WebOwner{run_id, node_id, site_key}`，贯穿 `执行器 → 节点 → dom_web_client → upload_registry → webview_host`；窗口按 owner **独占**（同 owner 复用 / **同站点不同 owner ⇒ 各自独立窗口 / profile（`D-33②` · 真并行 · 后期需要的能力）** / 跨站点**不再靠"关旧窗"实现** —— 换站点只是取用**该站点自己的**窗口）。
2. **就绪**（`W-D3`）：三级判据 —— **窗口**（controller / webview 非空）→ **页面**（`readyState=complete` 且**实时 URL** 与目标站点一致）→ **交互态**（composer 命中 + 附件区 / file input 命中）。
3. **证据归属**（`W-D4`）：脚本槽 / 上传槽 / 网络回执 / 答案基线 / 轮询状态**按 owner 分桶**；回执必须绑定 owner，否则**不得**用于 `I18` 判定。
4. **复位与归因**（`W-D5` / `W-D6`）：运行级**复位**（干净会话页 + 等就绪；时机 = **首次 + 失败时** · `D-35③`）；错误文案分离**未就绪 / 无入口 / 被占用**三类。

## §4 修正设计

### 4.1 归属：`WebOwner` 贯穿 + **窗口表**（`W-D1` / `W-D2`）

- **定义**：`struct WebOwner { std::string run_id; std::string node_id; std::string site_key; }`（`site_key` 沿用 `PB2-18` 的 `site_key_of(login_url)` 语义）。
- **传递**：执行器为每个节点建立 `RunContext`（`run_id` + `node_id`）→ 传给 `ProviderConfig` / `LLMGenerate` / `VLMGenerate` → `ai/dom_web_client.*` → `ai/upload/upload_registry.*` → `web/webview_host.*`；
  API 形态（示意，落地按现有风格定名）：`run_script_sync(owner, site_request, …)` / `set_file_input_files(owner, site_request, …)` / `begin_resource_capture(owner)` / `take_resource_capture(owner)`；`LoginRequest`（`web/site_ref.h:32-57`）增 `owner` 字段或改为独立参数。
- **窗口表**（`D-33②` 拍板 ⇒ **独立窗口 / profile · 真并行**）：`std::map<WindowId, Lease{owner, site_key}>` + `std::map<owner, WindowId>` 反查 ——
  - 同 `owner` 且同站点 ⇒ **复用**（今天的"幂等路径"保留为**快路**，语义不变）；
  - **同站点、不同 owner** ⇒ **各自独立窗口 / profile**（**真并行**：不再排队、不再互相关窗）—— 这是 `D-33②` 的拍板结果，也是「后期需要」的能力；
  - **跨站点** ⇒ **不再关旧窗**：直接取用（必要时新开）**该站点自己的**窗口 ⇒ 今天 19:39:12「串行复用登录窗口：先关闭旧窗口」这条日志**应当消失**；
  - 仅当**显式**要求共享（将来某条目声明「共用窗口」）才回落到排队 —— **默认不排队**。
- **禁止隐式抢占**：任何「先关旧窗再开新窗」都必须由**窗口表**决策（或显式清理语义），而不是像今天这样「**谁调用谁关**」。
- **成本与代价（如实登记）**：每站点一份窗口 = 一份内存 + 一份 WebView2 controller + 一份 profile 目录（登录态**各自维护** —— 与"各站点各自登录一次"的既有产品语义一致）；收尾必须**逐窗口** `request_close()` + `join()`（`stop_login_window()` 扩展为遍历窗口表）；界面「打开登录窗口」也须落到**某窗口**（不再覆盖全部站点）。

### 4.2 就绪三级判据（`W-D3` · 不变量 `I25`）

| 级 | 判据 | 失败语义 |
|---|---|---|
| **L1 窗口** | `g_window != nullptr` **且** `g_webview != nullptr`（controller / page 已创建） | 「窗口未就绪」→ 可**等待 / 重试** |
| **L2 页面** | 实时读页面：`document.readyState` 为完成态 **且** `location.href` 的 `site_key` == 目标站点（**不再用 `g_request.url`**） | 「页面未就绪 / 站点不符」→ 可**复位 / 重试** |
| **L3 交互态** | composer 命中（`input_selector` 或自动识别）**且** 附件区 / file input 命中（**上传前必须满足**） | 「页面不在可交互态」→ 可**复位（回新会话页）+ 重试一次** |

- 统一入口：`wait_ready(owner, site_request, need{L1,L2,L3}, timeout)`；三级**逐级**判定 + **逐级日志**（谁在哪一级失败，一眼可辨）。
- 上传路径（`set_file_input_files` / `resolve_file_input_selector`）**必须**先过 L3；**L3 未过不得**按「形态不支持」报错（归因分离，见 4.4）。

### 4.3 证据与状态归属化（`W-D4` · 不变量 `I26`）

- `g_script_*` / `g_files_*` / `g_net_records` / 答案基线 / 轮询计数 ⇒ 全部按 `owner` **分桶**；或在调用处**带 owner 校验**，不匹配即拒绝（先做校验更小改动）。
- **网络回执必须绑定 owner**：回执记录产生它的 `(run_id, node_id)`；`I18` 判定**只采信本 owner** 的回执与页面证据。
- **答案基线绑定本轮 send**：`send` 携带 `owner` + 单调序号，poll 只接受「send 之后产生」的候选。

### 4.4 运行级复位与归因分离（`W-D5` / `W-D6`）

- **复位时机**（`D-35③` 拍板）= **首次 + 失败时**：① 本轮**第一次**用到该站点 ⇒ 复位到「新会话页」并等 **L2 / L3**；② 若 L2 / L3 判定失败 ⇒ **再复位一次**（单次重试、有上限），仍失败则按 §4.4 的归因报错。
- **复位动作（实现事实 —— 不许假想 API）**：当前 `webview_host` **没有**「重导航 + 等完成」的公开原语（全文件仅**开窗时** `Navigate` 一次，`:1088`；`NavigationCompleted` 只用于触发协议探测，`:1067`）⇒ 复位按下面两条落地，**不新增导航 API**：
  1. **首选（窗口级）**：「回新会话页」= **关该站点窗口 + 重开**（复用既有开窗路径，`login_url` 天然就是新会话页）；
  2. **可接受（交互态级）**：只做 `wait_ready(L1→L2→L3)` —— **不重开、不动用户会话**。
- **不允许**：在**用户可见的共享窗口**里静默改导航（`location.href=…` 式）—— 会污染浏览历史且无「完成」等待；若将来确需，另立 `navigate_and_wait()` 原语（不在本补丁内）。
- **归因分离**（三类错误文案独立，各带 `owner` / `site` / 失败级 与**可操作下一步**）：
  1. 「**页面未就绪**（页面级 / 交互态）」→ 指引：等待 / 复位 / 检查窗口尺寸（视口）；
  2. 「**站点无上传入口**（形态不支持）」→ **仅在 L3 通过后**仍无候选时才允许下此结论；
  3. 「**该站点窗口被其他 `owner` 占用**」→ 指引：**取用 / 另开该站点自己的窗口**（`D-33②` 独立窗口 / profile · 真并行）；仅在**显式共享**模式（条目声明"共用窗口"）下才需要串行化。

### 4.5 自动识别的边界（`W-D7`）

- `attach_selector` 未回填 ⇒ 仍可自动识别（**兜底**，但**必须先过 L3**）。
- `answer_selector`（`D-34①` 拍板）= **维持「可选」· 不设人工必做门槛** —— 直接用**真机实测**驱动：未回填时运行期自动识别照跑；`AW-04` 以真机结果为准（**一旦复现**"命中布局容器 / 12 字节类假成功"即按 `PW-07` **立即修**：判据加固由**实测推动**，而不是预先设卡）。
- `PW-07`（**真机驱动加固** · `D-34①` 的伴随项）：候选池**收窄**（剔除 / 降权 `article`、`[role=listitem]`）+ **排除布局与导航祖先**（`aside` / `nav` / `header` / `footer` / `[class*=sidebar]`）+ **持续增长判据**（连续 N 轮未稳定 / 仍在增长才算回答）+ **命中明细打印**（选择器 / 命中数 / 字符数 / 文本前 60 字）+ **取消「短候选也算成功」**（`ai/dom_web_client.cpp:209-212` 的 fallback 分支改为 `found=false` + **显式 warning**，从根上杜绝 12 字节"假成功"）。

### 4.6 模板占位符静默（`W-D8` · 可选 · 归 M8 侧）

`PromptTemplate`：模板里存在**未被任何输入填充**的 `{...}` 占位符时 ⇒ **报错**（Console + 节点失败），不再「原样保留」。
（`nodes/local_nodes.cpp` 的「未匹配原样保留」注释口径需一并修订；**不改**「`{vars}` 仅在 1 个值时提供」的既有语义 —— 那是有意约定。）

### 4.7 `web.attach` 降级为诊断字段（`D-36②` · 数据模型 · `M8-Q1` 结案）

- **拍板**：字段**保留解析**，但**明确定位为只读诊断** —— **不得**用作「入口形态」的**分发依据**；`M8-Q1`（「`web.attach` 是否升级为入口形态契约」）据此**结案**。
- **依据（实测，非推测）**：入口形态是**运行时事实**，会随**视口 / 登录态 / 交互态**变化（`§0.2` 第 5 条：豆包小视口 = 无 `input[type=file]`、大视口 = 有；附件区未挂载 = **0 个**）⇒ 写成条目**静态声明必然误导**（正是本轮 41 ms 那类错误的温床）。
- **落地（`PW-13`）**：
  - 注释改写为「**诊断回显，不作为分派依据**」：`ai/provider_spec.h:78-80` · `web/site_ref.h:54-56`；
  - `--web-dom-dump` / `--upload-selftest` 就绪度行**回显实测形态**（`file_input` / `drop_zone` / `paste_only` / `none`）与当期计数；
  - 运行时读取 `attach` 的代码保持**零消费**（今天已是如此：`provider_spec.cpp:803` / `site_ref.h:94` 仅解析与携带）。
- **兼容**：`allowed_web_fields()`（`provider_spec.cpp:233`）**保留** `attach` —— 用户表里已填的值**不会**被报「未知字段」（`collect_unknown`，`:247-261`；该函数只产生 warning，不拒绝）。

### 1.2 代价如实登记（不是白拿）

| 编号 | 代价 | 说明 |
|---|---|---|
| `R1` | **每站一套协议适配器 · 抗改版 ≈ 0** | 站点改一次接口上传链路**必坏且无兜底**；native HTTP **不是**通用方案 |

## 2. 目标架构

### 2.1 文字生成（Phase 1 回滚后）

```
节点 / 面板 → ai/dom_web_client.cpp（WebView2 版：ensure_session + run_script）
           → web/webview_host.cpp（WebView2 常驻 + profile ~/.brain-ai/webview2）
           → 站点 DOM（逐字轮询）        ← 生产路径无 Python、无管道、无守护进程
```

- `builtin:deepseek` 协议栈（`ai/deepseek_web_client.cpp`）**继续有效**（`M7B` 的退役计划作废）；
- profile 继续用 `~/.brain-ai/webview2`（`paths::webview2_profile()`）；
- **不变量 `I2` 恢复效力**；`M7B` 的 `I20`（CLI 契约）与通道无关 ⇒ **保留**。

### 2.2 图片上传（Phase 2 起新建）

```
图片节点 + 生效 mode=web
  → [供料] web/webview_host（WebView2 会话）：Cookie / device_id / 站点签名
  → [上传] ai/image_upload_client.{h,cpp}（C++ 原生 HTTP · httplib · 每站一个适配器）
        ① prepare_upload  ② ApplyImageUpload  ③ TOS 直传（PUT 预签名 URL）  ④ CommitImageUpload
  → [判据] 站点接口响应体（我们**就是** HTTP 客户端 ⇒ 响应即证据）+ 面板 / 节点状态
```

- **落点**：新增 `source/src/ai/image_upload_client.{h,cpp}`（**首个站点 = 豆包 `doubao-web`**，契约抽象 + 每站一个适配器实现）；
- **配置表**：`providers.json` 的 `web` 段新增**上传字段组**（字段名**待拍板** → §7 `M8-Q1`）；
- **不变量 `I23`（新增）** → §11。

### 2.3 与旧通道的对应关系

| `M7B` 通道（退场） | 方案 E 对应物 |
|---|---|
| `web/pydoll_channel.*` + `web/pipe_client.*` + `web/channel_frames.*` | `ai/image_upload_client.*`（**纯 C++，无 IPC**） |
| Python `brain_ai_browser/daemon.py`（`_cmd_upload_image` / `_cmd_send_prompt` / `_cmd_read_answer`） | 直接消失（**无等价物** —— 文字与上传分属两条路） |
| 协议词表 §6.1（v4 · 10 命令 / 8 事件） | **不再需要**（作为资料归档保留） |
| `MB-D0-8` 登录态四层（L1~L4） | L1 干净退出 / L3 自愈 attach 概念**沿用**到 WebView2（原生持久 profile）；**L2 加密快照随之退场** |

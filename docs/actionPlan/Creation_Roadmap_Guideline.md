## §0 文档元信息与约定

### 0.1 定位

- **本文是创作流程的框架文档**：描述「小说/剧本创作从 0 到 100 经历哪些阶段、每阶段的数据形态、现有节点覆盖情况、缺口」。
- **本文是节点设计的依据**：L2 的文本处理节点（`TextSplit` / `TextReplace` / `TextExtract` / `TextClean` / `TextStats` / `TextDiff`）从本文的「原子操作清单」推导。
- **不改他文**：本文对 [`M_node_expansion.md`](../Archive/actionPlan/M_node_expansion.md) / [`../ai_writer_nodes.md`](../ai_writer_nodes.md) / [`../roadmap.md`](../roadmap.md) 等**只单向引用**。

### 0.2 本文要解决的那一个问题

> 「AIWriter 要服务小说/剧本创作 —— 但创作过程本身是什么样？每个阶段需要什么？现有节点覆盖到哪？缺什么？」

### 0.3 执行原则

1. **从创作过程出发，不从场景片段出发**：场景是流程的局部，流程是场景的容器。
2. **原子操作是流程的最小单元**：任何具体场景都是原子操作的组合。
3. **缺口登记，不预设结论**：发现缺口 → 登记 → 后续讨论，不直接开工。

## §1 创作流程骨架（8 阶段）

### 1.1 全景

```
【0-10】 构思          → 灵感、前提句、题材、基调、主题、目标读者
   ↓
【10-20】世界观 / 设定  → 规则、历史、地理、势力、系统
   ↓
【20-30】角色          → 档案、背景、动机、恐惧、欲望、关系、弧光
   ↓
【30-40】大纲 / 情节    → 三幕结构、章节分解、关键节拍、支线
   ↓
【40-50】场景分解      → 章节 → 场景（POV / 地点 / 时间 / 目标 / 冲突 / 结果）
   ↓
【50-75】草稿 / 正文    → 逐场景写作、扩写、续写、改写
   ↓
【75-90】修订          → 结构修订、行级编辑、一致性检查、声音统一
   ↓
【90-100】定稿 / 输出   → 格式化、导出、投稿准备
```

### 1.2 三幕结构映射

| 创作阶段 | 故事结构对应 |
|---|---|
| 构思 / 世界观 / 角色 | **前提**（故事的"是什么"） |
| 大纲 / 情节 / 场景分解 | **结构**（故事的"怎么走"） |
| 草稿 / 正文 | **第一幕 / 第二幕 / 第三幕**（故事的"写出来"） |
| 修订 / 定稿 | **打磨**（故事的"改到好"） |

## §2 逐阶段详解

### §2.1 【0-10】构思

| 项 | 内容 |
|---|---|
| 人在做什么 | 灵感记录、前提句、题材 / 基调 / 主题 / 目标读者 |
| 数据形态 | 短文本、零散笔记、关键词 |
| 典型产出 | 一句话前提（logline）、题材标签、目标字数 |
| 现有节点 | N-01 输入 · N-06 生成 · N-03 模板 |
| 缺口 | 无显著缺口 |

**节点使用示例**：
```
N-01（输入：一句话灵感）
  → N-03（模板：「请扩写为 200 字的故事前提」）
  → N-06（生成）
  → N-01（保存前提句）
```

### §2.2 【10-20】世界观 / 设定

| 项 | 内容 |
|---|---|
| 人在做什么 | 设定规则、历史、地理、势力、魔法/科技系统 |
| 数据形态 | 结构化条目（如「势力：名称/特点/关系」）+ 长文说明 |
| 典型产出 | 设定条目列表、规则文档 |
| 现有节点 | N-01 · N-06 · N-03 |
| 缺口 | **从长文提取设定条目** → `CR-GAP-01` |

**缺口详情**：
- AI 生成的设定往往是长文（如「世界有三大势力…」）
- 下游节点需要**结构化条目**（如「势力：A / 特点：… / 关系：…」）
- **需要「提取」原子操作**

### §2.3 【20-30】角色

| 项 | 内容 |
|---|---|
| 人在做什么 | 角色档案、背景故事、动机、恐惧、欲望、关系、弧光 |
| 数据形态 | 结构化档案（如「姓名/年龄/性格/目标/关系」）+ 描述文本 |
| 典型产出 | 角色档案卡、关系图 |
| 现有节点 | N-01 · N-06 · N-03 · N-04（合并多角色信息） |
| 缺口 | **从描述提取角色档案** → `CR-GAP-02` |

**缺口详情**：
- AI 生成的角色描述是散文
- 需要提取为「档案卡」供后续场景调用
- **需要「提取」原子操作**

### §2.4 【30-40】大纲 / 情节

| 项 | 内容 |
|---|---|
| 人在做什么 | 三幕结构、章节分解、关键节拍、支线 |
| 数据形态 | 结构化大纲（章 → 节 → 场景）+ 每章概要 |
| 典型产出 | 章节列表、每章节拍 |
| 现有节点 | N-01 · N-06 · N-03 |
| 缺口 | **长文拆分** → `CR-GAP-03`；**从长文提取章节结构** → `CR-GAP-04` |

**缺口详情**：
- 大纲常有几千字，**一次性送 AI 会超 token 上限**
- 需要按章节拆分，逐章生成
- **需要「拆分」+「提取」原子操作**

### §2.5 【40-50】场景分解

| 项 | 内容 |
|---|---|
| 人在做什么 | 章节 → 场景（POV / 地点 / 时间 / 目标 / 冲突 / 结果） |
| 数据形态 | 场景卡片（结构化）+ 场景序列 |
| 典型产出 | 场景列表、POV 分布表 |
| 现有节点 | N-01 · N-06 · N-03 · N-04 |
| 缺口 | **章节 → 场景拆分** → `CR-GAP-05`；**场景卡片结构化提取** → `CR-GAP-06` |

**缺口详情**：
- 章节是长文，场景是子单元
- 需要**按场景边界拆分**
- **需要「拆分」+「提取」原子操作**

### §2.6 【50-75】草稿 / 正文

| 项 | 内容 |
|---|---|
| 人在做什么 | 逐场景写作、扩写、续写、改写 |
| 数据形态 | 长文本（草稿） |
| 典型产出 | 章节正文 |
| 现有节点 | N-01 · N-06 · N-03 · N-04 · N-08 |
| 缺口 | **AI 输出清理** → `CR-GAP-07`；**长草稿分段** → `CR-GAP-08`；**模式化替换** → `CR-GAP-09` |

**缺口详情**：
- AI 输出常有前缀（「好的，以下是…」）、Markdown 标记、多余空行
- 需要**清理**
- 长草稿需要**分段处理**
- **需要「清理」+「拆分」+「替换」原子操作**

### §2.7 【75-90】修订

| 项 | 内容 |
|---|---|
| 人在做什么 | 结构修订、行级编辑、一致性检查、角色声音统一 |
| 数据形态 | 多版本文本、批注、差异 |
| 典型产出 | 修订稿、差异报告 |
| 现有节点 | N-01 · N-06 · N-03 · N-04 |
| 缺口 | **版本对比** → `CR-GAP-10`；**模式化替换** → `CR-GAP-11`；**清理** → `CR-GAP-12` |

**缺口详情**：
- 修订时需要对比新旧版本
- 需要**对比**原子操作
- **需要「对比」+「替换」+「清理」原子操作**

### §2.8 【90-100】定稿 / 输出

| 项 | 内容 |
|---|---|
| 人在做什么 | 格式化、导出、投稿准备 |
| 数据形态 | 最终文本 + 元信息 |
| 典型产出 | 成品文档 |
| 现有节点 | N-08 |
| 缺口 | 无显著缺口 |

## §5 B 档最终清单（从原子操作推导）

### 5.1 核心 4 项（流程必需）

| # | 节点 | 原子操作 | 支撑阶段 | 优先级 |
|---|---|---|---|---|
| 1 | `TextSplit` 文本分块 | 拆分 | 大纲、场景、草稿 | 高 |
| 2 | `TextExtract` 文本提取 | 提取 | 世界观、角色、大纲、场景 | 高 |
| 3 | `TextClean` 文本清理 | 清理 | 草稿、修订 | 高 |
| 4 | `TextReplace` 文本替换 | 替换 | 草稿、修订 | 高 |

### 5.2 辅助 2 项

| # | 节点 | 原子操作 | 支撑阶段 | 优先级 |
|---|---|---|---|---|
| 5 | `TextStats` 文本统计 | 统计 | 全阶段（字数管理） | 中 |
| 6 | `TextDiff` 文本对比 | 对比 | 修订 | 中 |

### 5.3 每项的参数面（初步）

#### `TextSplit` 文本分块

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `split_mode` | Enum | `by_separator` | `by_separator` / `by_length` / `by_paragraph` / `by_regex` |
| `separator` | String | `"\n\n"` | 分隔符（`by_separator` 模式） |
| `max_length` | Int | 2000 | 最大长度（`by_length` 模式） |
| `overlap` | Int | 0 | 重叠字符数 |
| `keep_separator` | Bool | false | 是否保留分隔符 |

#### `TextExtract` 文本提取

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `extract_mode` | Enum | `regex` | `regex` / `between` / `json_path` / `key_value` |
| `pattern` | String | `""` | 正则表达式（`regex` 模式） |
| `start_marker` | String | `""` | 起始标记（`between` 模式） |
| `end_marker` | String | `""` | 结束标记（`between` 模式） |
| `json_path` | String | `""` | JSON 路径（`json_path` 模式） |
| `output_mode` | Enum | `texts` | `texts`（变长）/ `text`（JSON） |

#### `TextClean` 文本清理

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `trim` | Bool | true | 去首尾空白 |
| `collapse_whitespace` | Bool | false | 压缩连续空白 |
| `remove_html` | Bool | false | 去 HTML 标签 |
| `remove_control_chars` | Bool | true | 去控制字符 |
| `dedup_lines` | Bool | false | 去重复行 |
| `remove_empty_lines` | Bool | false | 去空行 |
| `remove_prefix` | String | `""` | 去固定前缀 |

#### `TextReplace` 文本替换

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `pattern` | String | `""` | 查找模式 |
| `replacement` | String | `""` | 替换内容 |
| `use_regex` | Bool | false | 是否正则 |
| `case_sensitive` | Bool | true | 大小写敏感 |
| `max_replacements` | Int | 0 | 最大替换次数（0 = 不限） |

#### `TextStats` 文本统计

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `stats_mode` | Enum | `basic` | `basic` / `word_freq` / `all` |
| `top_n` | Int | 10 | 词频 top N |
| `output_mode` | Enum | `text` | `text`（JSON）/ `number`（端口） |

#### `TextDiff` 文本对比

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `diff_mode` | Enum | `line` | `line` / `word` / `char` |
| `context_lines` | Int | 3 | 上下文行数 |
| `output_mode` | Enum | `text` | `text`（统一 diff）/ `json` |

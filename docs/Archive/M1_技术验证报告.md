## 五、遇到的问题与解决方案（关键记录）

### 5.1 【已修复·最重要】节点画布首帧崩溃（0xC0000005）

- **现象**：完整界面启动后日志停在 `[首帧] DockSpace 完成`，进程无响应；退出码 `-1073741819`（0xC0000005 访问冲突），并留下无法终止的僵尸进程（占用 exe 导致后续链接报 `LNK1104 / LNK1168 cannot open aiwrite.exe`）。
- **定位手段**：① 用分阶段参数排除 OpenGL / ImGui / 停靠层；② 在 `NodeEditorDemo::draw()` 内加细粒度日志，确认崩溃点落在 `apply_editor_style()`。
- **根因**：`imgui_node_editor_api.cpp:96` 中 `ed::GetStyle()` 的实现为 `return s_Editor->GetStyle();`，即**依赖“当前编辑器”**。我们在 `ed::CreateEditor()` 之后、`ed::SetCurrentEditor()` 之前就取样式 → `s_Editor == nullptr` → 空指针解引用崩溃。
- **修复**：`ensure_context()` 改为先 `ed::SetCurrentEditor(g_context);` 再 `apply_editor_style();`（源码内已写注释）。
- **经验**：node-editor 的 `GetStyle / PushStyleColor / PushStyleVar` 等接口都作用于“当前编辑器”，必须先 `SetCurrentEditor`；M3 自绘节点时同样遵守。

### 5.2 CMake 的安装方式（系统 CMake + vcpkg 专用 CMake）

- **工程构建**：winget 安装的 **CMake 4.4.3**（`C:\Program Files\CMake\bin`，已写入机器 PATH）+ `Visual Studio 18 2026` 生成器。
  CMake 会自动准备 MSVC 环境，因此**不需要** Developer Prompt / vcvars64，VS Code、Visual Studio 2026（打开 `build/aiwrite.slnx`）与命令行都能直接构建。
- **vcpkg 端口构建**：本快照（2024-04）的 ports 声明 `cmake_minimum_required(VERSION 3.1)` 且缺少 `CMAKE_POLICY_VERSION_MINIMUM` 逃生口，用 CMake 4.x 会直接失败；
  故 `install-deps.cmd` 会把工程自带的 `third_party/cmake-3.31.6` 置于 PATH 最前，**仅用于安装依赖**。两者互不干扰。

### 5.3 vcpkg manifest 基线

- vcpkg 2024-04 要求 manifest 显式声明基线，已在 `vcpkg.json` 写入 `builtin-baseline = eb0f108…`（等于 `C:\dev\vcpkg` 的 HEAD）。
- 该版本会因环境差异计算不同 ABI 哈希而重新编译依赖，故 **CMake 配置阶段关闭自动安装**（`VCPKG_MANIFEST_INSTALL=OFF`），依赖统一由 `install-deps.cmd` 预装到 F: 盘安装树 + 二进制缓存，避免误写 C 盘与重复编译。

### 5.4 依赖发现（find_package）细节

- Windows 上 CMake 的 config 模式不会搜索 `<prefix>/share/<pkg>/`，需要把 vcpkg 安装树的 `share` 目录也加入 `CMAKE_PREFIX_PATH`（已在 `CMakeLists.txt` 显式追加）。
- `tomlplusplus` 端口**不提供 CMake config**（只有 pkg-config 与裸库），已在 CMakeLists 中手工建立导入目标（区分 Debug/Release 库）。
- `webview2` 端口的目标名是 `unofficial::webview2::webview2`（配置文件为 `unofficial-webview2-config.cmake`）。

### 5.6 【已修复·重要】WebView2 控制器创建静默失败（HWND=null → E_INVALIDARG 0x80070057）

- **现象**：`webview2_login` 的日志停在「WebView2 环境创建成功」后再无下文（自 M1 起一直如此，**控制器创建与导航回调从未触发**），表现为"能起窗口，但页面/登录/提取都无法验证"。
- **根因**：`CreateCoreWebView2EnvironmentWithOptions` 的异步回调可能在 `CreateWindowExW` **返回之前**（嵌套消息泵）就被触发，此时全局 `g_window` 尚未赋值 → `CreateCoreWebView2Controller(nullptr, ...)` **同步返回** `0x80070057 (E_INVALIDARG)`，而代码只检查了外层调用的 HRESULT，回调不触发又不报错 → 完全静默。
- **处理**：① `WM_CREATE` 开头先 `g_window = window;`（用 hwnd 参数初始化，消除时序依赖）；② 「隐藏窗口」由 `SW_HIDE` 改为**离屏可见窗口**（`SW_SHOWNOACTIVATE`）——WebView2 不会为完全隐藏的父窗口创建控制器；③ 补充 `CreateCoreWebView2Controller` **同步 HRESULT** 的日志与自检退出码。
- **验证**：`--selftest` 由"30 秒超时"变为 **1.2~2.1 秒 PASS**（Cookie 5 条）。

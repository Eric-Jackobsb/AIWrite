## §0 文档元信息与约定

### 0.1 定位

- **本文是上级节点的设计依据**：定义上级节点的概念、端口规则、参数暴露、执行语义、创建方式、存储、UI、禁止嵌套。
- **本文是节点扩展的架构补充**：与 [M_node_expansion.md](M_node_expansion.md) 的四层框架互补 —— 上级节点是「节点层」之上的「组合层」。
- **不改他文**：本文对 [`M_node_expansion.md`](M_node_expansion.md) / [`Creation_Roadmap_Guideline.md`](../../actionPlan/Creation_Roadmap_Guideline.md) / [`../../ai_writer_nodes.md`](../../ai_writer_nodes.md) 等**只单向引用**。

### 0.2 本文要解决的那一个问题

> 「通过底层节点的有机组合来形成一个上级节点，不用一个一个设计，而是进行程序化的生成」—— 这个「上级节点」是什么？怎么设计？

### 0.3 执行原则

1. **组合优于新增**：能用基础节点组合出来的，不新增基础节点。
2. **一层封顶**：上级节点**禁止嵌套**其他上级节点。
3. **用户自定义权**：可命名、可编辑、可组合。
4. **创作逻辑驱动**：上级节点的组合服务于创作过程（[Creation_Roadmap_Guideline.md](../../actionPlan/Creation_Roadmap_Guideline.md) 的 8 阶段）。

### 0.4 本轮范围

| 做 | 不做 |
|---|---|
| 上级节点的完整设计（定义 / 端口 / 参数 / 执行 / 创建 / 存储 / UI / 禁止嵌套）· 与创作逻辑的关系 · 与 CR-GAP 的关系 | 任何 `source/**` 代码改动 · 实施排期 · 具体 UI 原型 |

### 0.5 术语约定

- 节点统一写作「**代号 + 说明**」形式（如 `N-03 PromptTemplate 提示词模板`）。
- **基础节点** = 现有 **14**（MVP 8 + L2 6）。
- **上级节点** = 本文定义的新概念（Composite Node）。

## §1 结论摘要

**上级节点（Composite Node）= 由基础节点有机组合形成的迷你工作流，可命名、可自定义、可放入其他工作流、禁止嵌套。**

### 1.1 核心规则

| 项 | 规则 |
|---|---|
| **内部** | 由基础节点有机组合形成的迷你工作流 |
| **外部** | 像一个普通节点一样被使用 |
| **命名** | 用户可命名 |
| **自定义** | 用户可编辑内部组合 |
| **可放入** | 其他工作流 |
| **禁止嵌套** | 上级节点内部**不得**包含其他上级节点 |
| **输入端口** | 从内部标记的端口推导；**允许多个** |
| **输出端口** | **唯一**（强制单输出） |
| **参数暴露** | **选择性**（拖拽参数到暴露区） |
| **预览** | 父工作流中只读预览 |
| **编辑** | 独立编辑标签页 |

### 1.2 十项设计决策

| # | 议题 | 结论 |
|---|---|---|
| 1 | 输入/输出端口 | 自动推导（从内部标记的端口）+ 强制定义；多输入可以，输出唯一 |
| 2 | 参数暴露 | 选择性（设计时标记） |
| 3 | 执行语义 | 展开执行 |
| 4 | 创建方式 | 两者都要（打包 / 新建） |
| 5 | 编辑入口 | 独立标签页 |
| 6 | 存储 | 独立文件 |
| 7 | 节点库位置 | 独立分类「上级节点」 |
| 8 | 版本管理 | 无版本 |
| 9 | 与工作流关系 | 等同（上级节点 = 简化的工作流） |
| 10 | 禁止嵌套 | 两者都要（编辑时禁止 + 校验拒绝） |

### 1.3 架构位置

```
【上级节点层】  ← 组合体（程序化生成 / 用户自定义）
      ↑
【基础节点层】  ← 现有 14（MVP 8 + L2 6）
      ↑
【原子操作层】  ← 最小单元
```

## §2 上级节点的定义

### 2.1 核心定义

```
上级节点（Composite Node）
├─ 内部：由基础节点有机组合形成的迷你工作流
├─ 外部：像一个普通节点一样被使用
├─ 命名：用户可命名
├─ 自定义：用户可编辑内部组合
├─ 可放入其他工作流
├─ 禁止嵌套其他上级节点
├─ 输入：从内部标记的端口推导（多输入可以）
└─ 输出：唯一（强制单输出）
```

### 2.2 双重身份

| 视角 | 表现 |
|---|---|
| **外部**（在父工作流中） | 像一个普通节点：有输入端口、输出端口、参数 |
| **内部**（编辑时） | 是一个迷你工作流：多个基础节点 + 连线 |

### 2.3 与现有概念的关系

| 现有概念 | 与上级节点的关系 |
|---|---|
| 工作流 | 上级节点是「工作流的封装」—— 本质等同，封装层级不同 |
| 基础节点 | 上级节点的组成单元 |
| 节点库 | 上级节点进**独立分类**「上级节点」 |
| 参数面板 | 上级节点的参数 = 内部基础节点**暴露的参数** |
| 执行器 | 展开执行（内部节点展开到父图） |

### 2.4 命名规则

| 项 | 规则 |
|---|---|
| 命名权 | 用户 |
| 默认名 | 「未命名上级节点」 |
| 重名 | 允许（但文件 id 唯一） |
| 显示 | 节点标题显示用户命名 |

## §3 端口规则

### 3.1 输入端口

| 项 | 规则 |
|---|---|
| **数量** | **允许多个** |
| **推导方式** | 从内部**标记的端口**推导 |
| **标记时机** | 设计内部工作流时 |
| **类型** | 与内部对应端口一致 |

**推导机制**：

1. 用户在内部工作流中**标记**某个基础节点的输入端口为「上级节点输入」
2. 系统记录该端口 → 成为上级节点的输入端口
3. 多个标记 → 多个输入端口
4. 未标记 → 不作为上级节点输入

### 3.2 输出端口

| 项 | 规则 |
|---|---|
| **数量** | **唯一**（强制单输出） |
| **推导方式** | 从内部**标记的端口**推导 |
| **标记时机** | 设计内部工作流时 |
| **类型** | 与内部对应端口一致 |

**为什么强制单输出**：
- 上级节点的外部行为像一个普通节点
- 单输出保证下游连接清晰
- 多输出可通过内部 `TextSplit` 等节点在外部展开

### 3.3 端口标记的 UI 形态

| 方案 | 含义 |
|---|---|
| **甲：端口右键菜单** | 右键内部端口 → 「标记为上级节点输入/输出」 |
| **乙：拖拽到暴露区** | 拖拽端口到「端口暴露区」 |
| **丙：端口旁开关** | 每个端口旁有开关 |

**待实施前细化**。

## §4 参数暴露规则

### 4.1 规则

| 项 | 规则 |
|---|---|
| **暴露方式** | **选择性** |
| **标记时机** | 设计内部工作流时，**拖拽参数到「暴露区」** |
| **未标记的参数** | 固定在内部，外部不可见 |
| **暴露的参数** | 在父工作流的上级节点参数面板中可见可改 |

### 4.2 暴露的粒度

| 方案 | 含义 |
|---|---|
| **甲：参数级** | 逐个参数暴露 |
| **乙：节点级** | 整个节点的所有参数暴露 |
| **丙：混合** | 都支持 |

**本文采用**：**甲（参数级）** —— 精确控制。

### 4.3 暴露的 UI 形态

**「参数暴露区」**：

```
┌─────────────────────────────────────────┐
│  上级节点编辑（独立标签页）               │
│                                           │
│  ┌─────────────────┐  ┌───────────────┐ │
│  │                 │  │  暴露区        │ │
│  │   内部工作流     │  │                │ │
│  │                 │  │  · 参数A       │ │
│  │  [基础节点]      │  │  · 参数B       │ │
│  │                 │  │                │ │
│  └─────────────────┘  └───────────────┘ │
│                                           │
│  ← 拖拽参数到暴露区 →                     │
└─────────────────────────────────────────┘
```

**待实施前细化**。

### 4.4 暴露参数的默认值

| 项 | 规则 |
|---|---|
| 默认值 | 内部基础节点的参数值 |
| 外部修改 | 覆盖内部默认值 |
| 重置 | 可重置为内部默认 |

## §5 预览与编辑

### 5.1 权限矩阵

| 场景 | 预览 | 编辑 |
|---|---|---|
| **在父工作流中** | ✅ 只读预览 | ❌ 不可 |
| **进入独立编辑标签页** | ✅ 可以 | ✅ 可以 |

### 5.2 预览形态

**在父工作流中**：

| 方案 | 含义 |
|---|---|
| **甲：双击打开预览弹窗** | 弹窗显示内部结构（只读） |
| **乙：悬停显示缩略图** | 悬停显示内部缩略图 |
| **丙：右键「预览内部」** | 右键菜单 |

**待实施前细化**。

### 5.3 编辑入口

**独立编辑标签页**：

| 项 | 规则 |
|---|---|
| 入口 | 双击上级节点 / 右键「编辑」 |
| 形态 | 独立标签页（与工作流标签页并列） |
| 内容 | 内部工作流（基础节点 + 连线） |

- 内部工作流可能复杂，需要大空间

## §7 执行语义

### 7.1 展开执行

**含义**：执行时把上级节点的内部节点**展开到父图**执行。

**执行流程**：

```
父工作流执行到上级节点A
      ↓
展开A的内部节点到父图
      ↓
按拓扑顺序执行内部节点
      ↓
内部输出传递给父图的下游
```

### 7.2 与现有执行器的关系

| 项 | 说明 |
|---|---|
| 现有执行器 | 单线程分帧，`tick()` 每帧推进一个节点 |
| 展开后 | 内部节点成为父图的一部分，同样按帧推进 |
| 运行态 | 内部节点的运行态值统一在 `Executor::NodeOutputs` |
| 状态 | 内部节点状态统一在 `Graph` 中 |

### 7.3 优点

| 优点 | 说明 |
|---|---|
| 与现有执行器一致 | 不需要子执行器 |
| 运行态统一 | 快照 / 输出面板 / 错误条一致 |
| 调试简单 | 内部节点的日志与基础节点一致 |

### 7.4 待实施前细化

| # | 项 |
|---|---|
| 1 | 展开的时机（执行前 / 执行中） |
| 2 | 展开后的节点 id 命名（避免冲突） |
| 3 | 展开后的状态回写（内部状态是否显示） |

## §8 创建方式

### 8.1 两种创建方式

#### 方式甲：打包已有节点

**流程**：
1. 在画布上选中多个基础节点
2. 右键 → 「打包为上级节点」
3. 系统生成上级节点，内部 = 选中的节点
4. 用户命名
5. 用户标记输入/输出端口
6. 用户标记暴露参数
7. 保存

**优点**：从已有组合，快速。

#### 方式乙：从空新建

**流程**：
1. 节点库 → 「上级节点」分类 → 「新建上级节点」
2. 进入独立编辑标签页
3. 添加基础节点 + 连线
4. 标记输入/输出端口
5. 标记暴露参数
6. 命名
7. 保存

**优点**：从空开始，灵活。

### 8.2 两种方式都要

用户可以：
- 从已有节点打包（快速）
- 从空新建（灵活）

## §11 禁止嵌套的实现

### 11.1 规则

**上级节点内部不得包含其他上级节点。**

### 11.2 实现方式（两者都要）

#### 预防：编辑时禁止

**上级节点编辑标签页中，节点库不显示「上级节点」分类。**

| 优点 | 说明 |
|---|---|
| 预防为主 | 用户无法放入 |
| UI 明确 | 不会误操作 |

#### 校验：放入后拒绝

**即使通过其他方式（如粘贴 / 导入）放入上级节点，校验时拒绝。**

| 优点 | 说明 |
|---|---|
| 兜底 | 防御绕过 |
| 错误明确 | 给出可操作提示 |

### 11.3 校验时机

| 时机 | 说明 |
|---|---|
| 编辑时 | 放入上级节点 → 立即报错 |
| 保存时 | 保存前校验 |
| 加载时 | 加载时校验 |
| 执行前 | 运行前校验 |

## §12 与创作逻辑的关系

### 12.1 三层结构

```
【创作逻辑层】  ← 骨架（8 阶段 + 原子操作 + 状态结构）
      ↓ 实例化
【上级节点层】  ← 组合体（程序化生成 / 用户自定义）
      ↓ 由…组成

```

### 12.2 各层职责

| **上级节点层** | 定义「能力如何组合」 |
| **基础节点层** | 定义「能力的实现」 |

### 12.3 创作逻辑驱动上级节点

| 创作阶段 | 可能的上级节点 |
|---|---|
| 构思 | 「前提生成」= 输入 + 模板 + 生成 |

| 角色 | 「角色设计」= 输入 + 模板 + 生成 + 提取 + 清理 |
| 大纲 | 「章节拆分」= 输入 + 分块 + 生成 |
| 场景 | 「场景卡片」= 输入 + 模板 + 生成 + 提取 |
| 草稿 | 「章节生成」= 输入 + 上下文 + 生成 + 清理 |
| 修订 | 「一致性检查」= 提取 + 对比 + 报告 |
| 定稿 | 「格式化输出」= 清理 + 导出 |
